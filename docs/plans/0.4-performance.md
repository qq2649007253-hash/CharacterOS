# 性能更新与后续计划

## 已实施

- 知识文档增加角色与创建时间复合索引，匹配资料列表查询。
- 知识片段增加文档 ID 索引，减少背景资料更新时的片段删除扫描。
- 记忆访问时间去重后批量更新，每批最多 500 个 ID，事务内执行。
- 语义检索在 SQL 层限制 64 条片段，避免全部读取后再截取；关键词检索保持原有范围。

## 可复现基准

执行 `node scripts/benchmark-performance.mjs`。使用内存 SQLite 合成数据，不读取个人数据库。50,000 条文档、100 个角色、单次返回 500 条；每项预热 10 次后测量 100 次。

| 场景 | 更新前中位数 | 更新后中位数 | 更新前 P95 | 更新后 P95 |
| --- | --- | --- | --- | --- |
| 按角色读取文档 | 1.121 ms | 0.150 ms | 1.233 ms | 0.194 ms |
| 更新 100 条记忆访问时间 | 0.087 ms | 0.028 ms | 0.103 ms | 0.031 ms |

测量日期：2026-09-14，本机 Windows。计时只包含同步 SQL；不包含模型、网络、磁盘持久化或浏览器渲染。记忆 benchmark 对比等价 SQL，不是端到端聊天测试。正常检索最多更新 6 条记忆，不能用 100 条批量成绩代表日常体验。索引以 IF NOT EXISTS 自动建立，首次启动大数据库可能增加建索引时间与磁盘占用。

## 下一步建议

1. 图片：三张默认 PNG 合计约 7.1 MB，生成 WebP/AVIF 展示副本和尺寸变体；保留原图，验收清晰度与总传输字节。
2. 首字延迟：单独记录检索、向量生成、模型首字和完整回复时间；预先构建知识向量，避免第一次聊天临时生成。
3. 流式界面：当前每个网络片段触发消息更新，可按 30–50 ms 合并渲染；验证取消、尾段和中文解码不丢失。
4. 大量历史：会话列表改为分页加载，需同步提供加载更多入口，避免直接截断旧对话。
5. 语音：先测量在线合成耗时分布，再评估分句播放与有界缓存；必须处理取消、顺序与声线变更。

发布前仍需真实机器上的首字延迟、启动耗时和长会话内存测试。此次不承诺模型生成速度改善，不自动发布安装包。
